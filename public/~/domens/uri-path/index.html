URL Path Characters

Allowed symbols after the domain name.

Introduction

This page documents every character that may appear in the path component of a URL — the part that comes after the domain name and before the query string or fragment.

For example, in the URL https://example.com/docs/api/v2#section, the path is /docs/api/v2. This document covers exactly which characters are legal inside that path, which of them must be percent-encoded, and which are reserved for structural purposes.

The rules described here are defined by RFC 3986, the current standard for Uniform Resource Identifiers (URI), published in January 2005.

Reserved Characters

Reserved characters have a special structural meaning in a URI. They are split into two groups: general delimiters (gen-delims) and sub-delimiters (sub-delims). Inside the path component, only some of them may appear literally.

Unreserved Characters

Unreserved characters are the safest choice for URL paths. They are never interpreted as delimiters and never need percent-encoding. RFC 3986 explicitly recommends using only these characters when designing new URIs.

Why These Characters Are Recommended

  • They are not reserved for any structural role in a URI.
  • They are interpreted identically whether encoded or not — a and %61 mean the same thing.
  • They are safe across all transport protocols, proxies, gateways, and user agents.
  • They are human-readable and easy to type.
  • They do not conflict with any URI component delimiter.

Percent-Encoding

RFC Reference

The authoritative specification for URI syntax is:

RFC 3986

Uniform Resource Identifier (URI): Generic Syntax

Authors: T. Berners-Lee, R. Fielding, L. Masinter

Date: January 2005

Status: Internet Standard (STD 66)

Relevant sections of RFC 3986:

  • Section 2 — Characters (unreserved, reserved, percent-encoded).
  • Section 3.3 — The Path component and its ABNF grammar.
  • Section 2.1 — Percent-Encoding definition.
  • Section 2.2 — Reserved characters.
  • Section 2.3 — Unreserved characters.

ABNF grammar for the path component (simplified):

path          = path-abempty    ; begins with "/" or is empty
              / path-absolute   ; begins with "/" but not "//"
              / path-noscheme   ; begins with a non-colon segment
              / path-rootless   ; begins with a segment
              / path-empty      ; zero characters

pchar         = unreserved / pct-encoded / sub-delims / ":" / "@"

This grammar shows that a path segment (pchar) may contain unreserved characters, percent-encoded triplets, sub-delimiters, and the characters : and @. The slash / is only allowed as a separator between segments.
